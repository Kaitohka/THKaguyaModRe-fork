## 2. 按「量级 × 可修性」排序的行动建议

1. **A2 + A3（网络）**：先断掉「每 tick 脏数据」再降 `clientTrackingRange`。这是唯一能让包量/服务端短命对象数**成数量级下降**的一组，且不触碰弹幕手感。注意只调 `updateInterval` 无效（`isDirty()` 绕过）。
2. **A1（每 tick 基础 tick）**：一条 `updateInWaterStateAndDoFluidPushing()` 覆写即可砍掉每弹每 tick 的 8 次流体查询与 2 个 `BlockPos`，改动面极小、风险可控。
3. **A4（弹尺寸）**：既是性能也是正确性（大弹命中盒/渲染距离），需要小范围实测确认 `getDimensions` 的调用时序。
4. **A5 + A6 + A7（渲染）**：CULL 变体 + RenderType 键/预缓存 + fixed buffer 注册，属于客户端帧时间与 overdraw 的主要来源；`MasterSpark`（845 quad/通道）叠加 NO_CULL 时最明显。
5. **B1（homing 节流）**：结构属 1.7.10 设计，但绝对量级最高，按既定 R5 待办做目标缓存节流。
6. 其余（A8~A13、B2~B6）为摊薄型优化，按需做。
