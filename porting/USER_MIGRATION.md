# 五つの難題MOD+ / Itutu no Nandai MOD+ — 1.21.1 玩家迁移说明

> 适用版本：**2.90-1.21.1**（NeoForge 版）
> 面向对象：**已经玩过 1.7.10 版的老玩家**，以及第一次接触本模组的新玩家
> 文档定位：兼容性声明 + 行为差异清单 + 配置迁移 + 常见问题
> 文中「旧版」一律指 1.7.10 Forge 版 `THKaguyaMod` 2.90；「新版」指本 1.21.1 NeoForge 版。

## 1. 版本对应与获取

### 1.1 版本对照

| 项目 | 旧版（1.7.10） | 新版（1.21.1） |
|---|---|---|
| Minecraft | 1.7.10 | **1.21.1** |
| 模组加载器 | Forge（`cpw.mods.fml` 时代） | **NeoForge 21.1.252 或更高的 21.1.x**（`neoforge` 依赖范围 `[21.1.252,)`） |
| 显示名称 | Itutu no Nandai MOD+（五つの難題MOD+） | 同名 `Itutu no Nandai MOD+` |
| **modid** | `THKaguyaMod` | **`thkaguyamod`（全小写）** |

### 1.2 安装方式

1. 用官方安装器装好 **NeoForge 21.1.252（或同为 21.1.x 的更高版本）**，并确认启动器使用 **Java 21**。
2. 把 `thkaguyamod-2.90-1.21.1.jar` 放进 `mods/` 文件夹。
   - 单人游戏：装在自己这边即可。
   - 多人游戏：**服务端与客户端都要装**（模组声明为 `side=BOTH`）。
   - 局域网联机：房主与所有加入者都要装。
3. 不需要任何附加模组；没有"不装就崩"的前置。

### 1.3 modid 变成小写，会影响什么

现代加载器（NeoForge/Forge 1.13 以后）规定 modid 必须是全小写。旧版的 `THKaguyaMod` 里含大写字母，在新版里不合法，因此新版统一使用 **`thkaguyamod`**。
这与旧模组内部使用的资源域名（`assets/thkaguyamod/`）本来就一致，因此贴图、语言、音效等资源的路径逻辑没有变化。

对玩家的实际影响：

| 场景 | 旧写法 | 新写法 |
|---|---|---|
| 召唤生物 | `/summon THKaguyaMod.Cirno`（或用数字实体 ID） | `/summon thkaguyamod:cirno` |
| 给物品 | `/give <玩家> THKaguyaMod.miracleMallet` | `/give <玩家> thkaguyamod:miracle_mallet` |
| 数据包 / 资源包路径 | 资源域名本来就是小写：`assets/thkaguyamod/...` | 不变：`assets/thkaguyamod/...` |
| 配方与战利品表 id | 数字 ID / 无（1.7.10 无 JSON 配方体系） | `thkaguyamod:<snake_case>` |

**可直接用的实体 id 一览**（`/summon thkaguyamod:<id>`，共 46 个实体类型）：

- 杂兵与首领：`th_fairy`（妖精）、`sunflower_fairy`（向日葵妖精）、`th_phantom`（幽灵）、`familiar`（使魔）、`danmaku_creeper`（花田尖叫者 / 旧名 Hanabeeper）、`cirno`、`rumia`、`toziko`、`wriggle`、`reimu`、`miko`
- 商人角色：`sanae`、`sakuya`、`rinnosuke`
- 道具/效果实体：`cursed_decoy_doll`、`silver_knife`、`kinkakuzi`、`marisa_broom`、`mini_hakkero`、`hisou`、`nazrin_pendulum`、`sukima`、`mazinkyoukan`、`spiritual_strike_talisman`、`yuuka_parasol`、`private_square`（＝咲夜的怀表效果空间）、`sakuya_stop_watch`、`divine_spirit`、`th_item`、`shot_material`
- 弹幕与法阵：`normal_shot`、`normal_laser`、`set_laser`、`homing_amulet`、`musou_fuuin`、`nuclear_shot`、`onmyoudama`、`sanae_wind`、`dragon_neck_jewel`、`spell_card`、`spell_card_circle`、`miracle_circle`、`hakurei_shield`、`hakurou_reflecter`、`aja_red_stone_effect`、`cirno_ice_box`

## 2. 存档迁移声明

### 2.1 结论：**不支持把 1.7.10 存档迁移到本版本**

请**不要**在 1.21.1 中直接打开 1.7.10 的存档，也**不要**期待存档内容（建筑、箱子、玩家背包、成就）能带过来。请继续保留旧的 1.7.10 实例用于怀旧与查阅。

### 2.2 为什么不行

1.7.10 与 1.21.1 之间隔了约 10 年的注册表体系变革，主要断裂点：

| 层面 | 1.7.10 | 1.21.1 |
|---|---|---|
| 方块/物品身份 | 全局**数字 ID**（+ metadata 子类型） | **命名空间 id**（`thkaguyamod:xxx`）+ 方块状态/数据组件 |
| 物品数据 | NBT 标签（`Number`/`Speed`/`Color`/`Charge`/`Infinity` 等） | **数据组件**（DataComponent），键与结构完全不同 |
| 实体 | 数字 ID + `DataWatcher` 索引 | `EntityType` 注册名 + `SynchedEntityData` |
| 区块存储 | Anvil + 数字 ID 调色板 | 分段调色板 + 生物群系/高度图全面改写 |
| 配置 | `config/THKaguyaMod.cfg` | `config/thkaguyamod-server.toml` |

即使原版会尝试升级地形，模组内容（本模组的方块、实体、物品）**没有任何映射规则**，结果通常是：方块变成空洞、实体消失、物品消失或变成无法识别的残留数据。因此本版明确声明 **不提供存档迁移**，也没有编写任何旧存档修复器（DataFixer）。

### 2.3 补偿指引（建议按顺序做）

1. **先备份**：把旧 1.7.10 实例整个 `saves/` 目录复制一份存档，不要在原目录上做实验。
2. **导出物品与进度清单**（为在新世界重建做准备）：
   - 用旧版的物品栏/箱子查看类模组（如 NEI 一类）或直接截图，记录你拥有的**符卡、宝具、弹幕素材**数量；
   - 单人存档可用 NBT 查看工具打开 `level.dat` / `playerdata/*.dat` / 箱子数据，把物品的**显示名与数量**抄成表格（旧版的数字 ID 对新版无意义，只需记名字）；
   - 本模组物品名对照可参考本文 §3 与游戏内中文名（新版共 **126 个物品 + 10 个方块物品 = 136 项**，其中 **35 张符卡**）。
3. **新世界从头开始**：在新版开一个新世界，用创造模式按导出的清单给自己补回关键道具（宝具、符卡、万宝槌、时停道具等）。旧版本的"通关感"主要来自宝具与符卡收集，这部分重建成本不高。
4. **建筑重建**：地形与建筑无法迁移，只能重新盖；如果只是想继续玩玩法，建议直接开新世界，把宝具与符卡补齐即可。
5. **不要尝试"先升级原版再加载模组"**：中间版本同样无法识别 1.7.10 模组方块与实体，只会把内容抹掉。

> 一句话：**旧存档留在旧版本，新版本开新世界，用清单在创造模式补回关键物品。**

## 3. 玩家可见差异清单

下面按"功能 / 旧版行为 / 新版行为 / 原因"逐条列出。标注**（未完成）**的项目属已知缺口，详见 §5。

### 3.1 获取方式与配方

| 功能 | 旧版行为 | 新版行为 | 原因 |
|---|---|---|---|
| 万宝槌转换台：外部模组配方 | 把外部模组的"素体人偶"（`item.alicedoll.bare`）放进去，转换成**被诅咒的诱饵人偶** | **整条配方删除**，无法再用任何素材转出"被诅咒的诱饵人偶" | 该外部模组没有 1.21.1 版，物品链接无法建立 |
| 万宝槌转换台：楼观剑 → 楼观旋风刃 | 转换对象叫**楼观旋风刃**（`RoukanSenpuuzin`） | 产出物暂为**楼观剑本身**（耐久值原样保留） | 旧版的"楼观旋风刃"物品注册代码在原作里是被注释掉的半成品，从未真正注册；新版同样没有该物品 |
| "无配方物品"的补充配方 | 由配置项 `Add Recipeless Items Recipe` 控制，**默认关闭**（打开后才会追加这些配方） | 对应 8 条配方**改成常驻、始终可用**：水珍珠、白珍珠、冰剑、魔法扫帚、万宝槌、冰符「Icicle Fall」、月符「Moonlight Ray」、冻符「Perfect Freeze」 | 1.21.1 的配方是数据文件，是否启用不再由配置项控制；为让这些物品有正常获取途径而纳入 |
| 地牢里的小槌 | 原作写了"把地牢箱中的附魔书改写成小槌"的代码，但注册方法本身是**空的**，实际**从未生效** | 地牢箱（`chests/simple_dungeon`）现在**真的会刷出万宝槌**，单箱约 **0.77%** 概率（原设计意图为 5%，偏差已记录） | 新版用战利品表 + 战利品修饰器重建，实现的是原作的设计意图 |
| 刷怪蛋 | 每个模组实体都自动获得一个**刷怪蛋**（约 45 个），放在"杂项"栏 | **没有刷怪蛋**；创造模式请用 `/summon thkaguyamod:<id>`，或从主标签拿取人物/实体相关的展示物品 | 旧版的刷怪蛋是一段"巨型 if 链"的取巧实现，无法照搬；新版选择不提供 |
| 万宝槌转换界面的**打开方式** | 界面代码与注册都在，但物品里"潜行右键打开"的调用在旧版**被注释掉了**，正常情况下打不开 | **潜行 + 右键**万宝槌即可打开转换界面（正常可用） | 新版恢复了旧版未接通的入口（属于补全而非改玩法） |
| 御柱的挖掘减速 | 御柱被特意做成"挖得很慢"（挖掘效率恒为 3.0，比原版木剑还低） | **减速未实现（未完成）**，挖掘效率按木级材质计算（木级默认 2.0 附近，实际差距不大） | 1.21.1 没有物品级的挖掘速度覆写点，需要改用属性/事件实现 |
| 发射器发射弹幕 | 从发射器射出的弹幕，其"发射者"是一个妖精（该妖精会被生成出来） | 发射者改为**不进入世界、不可见的占位实体**（盔甲架），弹道与命中判定不变；**旧版会顺便在发射器前生成一只妖精，新版不会**（这只是旧实现的副产物） | 新版个别实体类有生命周期约束，占位实现可避免残留实体 |

| 蓬莱玉枝的充能图标 | 图标随"充能"分 **6 段**变化 | **图标不随充能变化**（未完成，模型 predicate 待补） | 现代版本需要用模型 JSON 的 `ItemProperties` 驱动贴图层 |

### 3.3 音效

旧版发布包在 `sounds.json` 里声明了 4 个音效事件，但 **`.ogg` 音效文件从未打包**（旧版靠硬编码路径探测以决定用不用自定义音效，实际基本用不到）。新版把这 4 个事件正规注册，但**暂用原版音效占位**：

| 事件 | 旧版 | 新版占位音 |
|---|---|---|
| `masterspark`（魔炮 / 迷你八卦炉 / 绯想之剑） | 自定义音效（实际缺失） | `minecraft:entity.lightning_bolt.impact` |
| `spellcard`（符卡宣言） | 自定义音效（实际缺失） | `minecraft:entity.player.levelup` |
| `sukima`（隙间） | 自定义音效（实际缺失） | `minecraft:entity.enderman.teleport` |
| `down`（残机复活） | 自定义音效（实际缺失） | `minecraft:entity.player.death` |

其他音效层面的差异：

- **隙间系列音效统一为末影人传送音**。配置项「Use default Gap(Sukima)SE」现在只影响音量/音高：`true` 用较轻柔的一次播放，`false` 用音量 1.0 的一次播放——听起来都是末影人传送音。旧版"自定义任意音效名"的字段已废弃（现代音效必须注册）。
- 投掷/发射类动作音效沿用原版近似音：蓬莱玉枝用经验球拾取音、万宝槌用箭矢发射音、时停表用按钮点击音等。

### 3.4 玩法机制

| 功能 | 旧版行为 | 新版行为 | 原因 |
|---|---|---|---|
| 魔法扫帚的**操舵** | 读取 W/A/S/D/空格：跳跃上升、S 后退、A/D 横移，可完全手动驾驶 | **暂为"朝骑手视线方向前进"**：骑上去后按住视线方向飞，没有独立的升降/横移键（未完成） | 1.21.1 的客户端按键输入不再能从实体侧读取"跳跃键"状态，需要另设输入通道 |
| 火鼠裘的"无限耐久" | 耐久上限为 0，永不损坏 | **仍然永不损坏**，但实现方式改为"不给物品任何耐久属性"；穿着时每 tick 清除自身着火，未附魔时自动附加火属性保护 | 现代版本用"有无耐久属性"表达可否损坏 |
| 火鼠裘的附魔等级 | 自动附加"火属性保护 V" | 组件里仍写 **V**，但 1.21.1 原版上限是 IV，实际生效等级可能被夹到 IV（待确认） | 原版附魔等级上限变更 |
| 时间停止（咲夜的怀表 / 停表） | 每 tick 扫描周边实体，**直接改写其内部状态**实现冻结与回滚 | 仍按"位置、朝向、移动量、`tickCount`、下落距离回滚"实现，观感基本一致；但**部分旧细节无法复现**：攻击动作回卷改为近似、爆炸引信/苦力怕膨胀计时等无法回卷（未完成） | 1.21.1 把若干内部计时字段收进私有实现，外部无法再改写 |

## 4. 配置迁移

### 4.1 文件位置与格式

| | 旧版 | 新版 |
|---|---|---|
| 文件 | `config/THKaguyaMod.cfg` | **`config/thkaguyamod-server.toml`** |
| 格式 | Forge `Configuration`（类 INI） | TOML（NeoForge `ModConfigSpec`） |
| 生效方式 | 启动时读取 | 启动/世界加载时读取，**修改后需重载或重启** |
| 分类 | EntityID / Limit / 效果 / SE vol / Danmaku / Other | Limit / Effect / SE vol / Danmaku / Other |
| 单世界覆盖 | 不支持 | 支持：把同名文件放到 `saves/<世界名>/serverconfig/thkaguyamod-server.toml` 可只对某个世界生效 |

### 4.2 EntityID 类别：**整体废弃**

旧版有 23 项 `EntityID` 配置（Fairy=530、Phantom=531、Cirno=561……），用于给模组实体分配数字 ID。
新版实体的身份是**命名空间 id**（`thkaguyamod:cirno`），由注册系统自动分配，**不存在也不需要一个可配置的数字 ID**。因此该类别在 TOML 中完全没有对应项，旧值无需、也无法迁移。

### 4.5 迁移建议

1. 打开旧版 `config/THKaguyaMod.cfg`，只记录 `Limit / Effect / SE vol / Danmaku / Other` 里你改过的值。
2. 启动一次新版，让它生成 `config/thkaguyamod-server.toml`，再照上表逐项改成你习惯的数值。
3. 想"只对这一张地图生效"，就把改好的文件复制到 `saves/<世界名>/serverconfig/thkaguyamod-server.toml`。
4. 数值范围比旧版更严格（如 `Shot Max Number` 上限 512）。超出范围的值会被夹到边界，不会崩溃。

## 6. 常见问题 FAQ

**Q1. 右键符卡没有反应，为什么？**
符卡宣言**必须瞄准一个生物**，不是对空气放的。规则如下：
- 视线前端 **32 格**内必须有一个**生物**（放线检测，可以被方块挡住）；**动物与村民不算**目标；
- 同一个玩家 **64 格内已经展开过符卡**时无法再宣言（避免叠加）；
- 非创造模式下要付代价：符卡需要"等级"，等级不足时可以用 **Bomb 道具**（`bomb_item`）抵扣，1 个道具顶 1 级，抵扣不够的部分会**扣你的经验等级**；
- 首次宣言会**回收（消弹）施法者周围 40 格内的敌方弹幕**。

**Q2. 早苗的符卡为什么用不了？提示也没有。**
早苗系的 5 张符卡（奇迹「Miracle Fruit」、奇迹「空中落物的奇迹」、妖怪退治「妖力掠夺者」、开海「摩西的奇迹」、大奇迹「八坂之神风」）需要**「奇迹之力」充能**才能宣言；充能为 0 时宣言会**静默失败**（旧版同样没有报错提示，新版保持一致）。
给符卡充能的方法：手持**风祝的驱魔棒**（早苗的祓棒），按住右键蓄力并画五芒星，达到要求后松手：

| 目标符卡 | 需要蓄力（tick） | 需要等级 |
|---|---|---|
| 奇迹「Miracle Fruit」 | 30 以上 | 20 |
| 奇迹「空中落物的奇迹」 | 60 以上 | 25 |
| 妖怪退治「妖力掠夺者」 | 90 以上 | 30 |
| 开海「摩西的奇迹」 | 120 以上 | 35 |
| 大奇迹「八坂之神风」 | 150 以上 | 40 |

充能成功后符卡会**发光**，提示行显示「奇迹之力 : 100%」。充能会随时间消耗——满充能是 1000 点，**每秒约掉 2 个百分点，约 50 秒耗尽**，用掉之前尽快宣言。

**Q3. 物品在创造模式哪里找？**
两个标签页：**「五难题MOD+」**（全部物品与方块，图标是蓬莱玉枝）与**「符卡」**（35 张符卡，图标是梦想封印）。它们**不再出现在原版"战斗/杂项/材料/装饰"栏**里。

**Q4. 怎么让模组的怪出现？**
- 自然生成：由 `config/thkaguyamod-server.toml` 的 `Spawn Danmaku Mob` 等开关控制（妖精在**草地/泥土/沙子地表且较亮**处，幽灵与首领在**暗处**，屠自古需要**雷雨**，琪露诺需要**雪地 + 附近有冰**，花田尖叫者需要**沙漠**且 `Spawn Hanabeeper` 为 true）；
- 手动召唤：`/summon thkaguyamod:cirno` 等（完整 id 见 §1.3）。新版没有刷怪蛋。

**Q4-1. 想清场怎么办？**
用 `/kill @e[type=thkaguyamod:cirno]`（换成对应 id 即可）。多个 id 需要分别执行。

**Q5. 为什么我打妖精没有双倍伤害？**
因为旧版就没生效——旧版的种族判定有 bug，导致"妖怪/妖精/幽灵 2 倍伤害"从未触发。新版为保持行为一致而没有"修好"它。这不是新版坏了。

**Q6. 万宝槌能做什么？**
三件事：
1. **右键**（不潜行）：把周围 20 格内**自己打出的弹幕**体积 +0.5；使用消耗 30 点耐久，放在背包里会每 tick 缓慢回耐久；
2. **潜行 + 右键**：打开"转换台"界面（把阴阳玉 → 血阴阳玉、隙间 → 隙间折叠伞、楼观剑 → 楼观剑）。注意外部模组素材的配方已删除，诅咒替身人偶无法转出；
3. 地牢箱子有小概率刷出万宝槌，也可用常驻配方合成。

**Q7. 时停道具怎么用？**
- **停表**（`sakuyas_stopwatch`）：右键立刻展开约 40 tick 的短时停止，非创造模式消耗 1 个。
- **咲夜的怀表**（`sakuyas_pocket_watch`）：
  - **创造模式**：右键（可按住约 1 秒）立刻展开停止空间，不消耗；
  - **非创造模式**：怀表有两种档位，用**潜行 + 右键**切换（档位可以从物品**是否发光**看出来）。受旧版实现的限制，**只有"半速"档位（物品不发光）能成功发动**，且发动的是"限时半速"空间（约 8 秒）；"停止"档位在非创造模式下按下不会有效果（旧版同样如此）；
  - 发动会消耗 1 个怀表。
- 两者都要求**周围 20 格内没有同类效果**，否则使用失败（不消耗）。

**Q8. 隙间怎么改颜色？**
- **隙间实体**：右手拿着**任意染料**，直接右键地上已经生成的隙间，颜色会立刻改成该染料的颜色（16 色编号与旧版一一对应）；
- **隙间折叠伞**：潜行右键循环切换颜色（循环值同时决定生成的隙间颜色，即使图标看起来没变）；
- **隙间物品**（`gap`）：旧版是"右键放置一对传送用的隙间，破坏时掉回物品"，新版沿用同一用法，颜色由上面的方式调整。
- 把**悔悟之棒**拿在手上右键隙间（或空手潜行右键）可以让隙间掉回物品。

**Q9. 弹幕工作台怎么用？**
右键"弹幕工作台"或"激光弹幕工作台"打开界面：把素材放进素材槽、按 3×3 形状矩阵摆放决定弹形、调整弹数/弹速/颜色/重力等数值槽，结果槽产出带参数的弹物品。参数上限受 `Shot Max Number` / `Laser Max Number` 影响。

**Q10. 残机（生命道具）怎么用？**
放在**背包里**即可，不需要手持。死亡时会自动消耗 1 个、原地满血复活并获得约 5 秒（100 tick）无敌。没有残机时会正常死亡。

**Q11. 早苗与咲夜的商店卖什么？**
- **早苗**：64 个"子弹之素"（`shot_material`）换 1 个病气平愈守；
- **咲夜**：16 个子弹之素换 1 把银质小刀；64 个子弹之素换 1 个停表。
两人都**不会**像原版村民那样随交易次数升级或解锁新交易（与旧版一致）；但每笔交易有次数上限（12 次），用完后该笔会暂时缺货，需等待恢复（见 §5 第 22 条）。

**Q12. 霖之助在哪里？**
他是独立的"商人型"村民，会在世界自然生成（概率较低，夜晚在暗处），可与玩家交易（用铁锭/金锭/红石/青金石/下界之星/灵力道具/得分道具换本模组的道具）。他**不绑定村庄职业**，不繁殖，走远后会自然消失。

**Q13. 我可以把 1.7.10 存档拷过来吗？**
不可以，请见 §2。旧存档请留在旧版本。

**Q14. 需要装什么前置模组？**
不需要。本版**没有**任何必需前置（也未与外部模组联动）。
