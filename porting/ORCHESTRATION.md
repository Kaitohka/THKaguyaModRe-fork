# 子代理编排协议（K3 主控 ↔ flash 执行）

> 生效：即时。适用范围：本项目内所有子代理调度。
> 目标：不影响 K3 主任务（架构/裁决/集成/验收）的前提下，自动利用空闲并发位处理相互独立的任务，避免重复执行与资源争用。

## 1. 触发条件（满足全部才派发新批次）

- 当前无 K3 手里的编译/回归在跑（主树处于稳定可编译态）；
- 任务与在途批次**无文件重叠、无共享可变状态**（由 K3 按模块边界判定）；
- 任务的依赖件（契约类/注册表/资源）已存在或已在简报中冻结为契约；
- 在途代理数 < 并发上限（见 §2）。

## 2. 数量上限与资源纪律

- **稳态并发上限：10 路**（经验值：13 路触发 429 限流）。
- 每路代理超时 2h；超时/429/520 一律**无损恢复**（resume 保留上下文），恢复时补「立即落盘、减少往返」指令。
- 单批次规模指导：≤30 个文件或 ≤4000 行；超出先拆批（实体批 18 类/渲染批 14-18 个为实证合适的粒度）。
- flash 简报统一要求：批量并行读取、减少请求往返。

## 3. 任务分配规则

- K3 负责：需求拆解、接口契约冻结、依赖排序、裁决、合并、验收。
- flash 负责：明确范围内的代码移植/修复，不做架构决策。
- 冲突/接口不清 → 代码留 `// TODO K3-review` + 报告上报，不得自行变更契约。
- 修复批（FIX）与移植批不重叠：FIX 批直接改主树，仅在主树编译破损时派发，范围限定到出错包。

## 4. 输入/输出格式（简报模板）

**输入（简报必填）**：背景与工程路径 / 只读参考文件清单 / 输出目录（staging 子区）/ 契约与既有设施 / API 映射要点 / 验收方式 / 报告要求。

**输出（报告必填）**：变更清单（文件+行数+一句话）/ 验证方式与结果 / 假定 API 清单 / TODO 与降级点 / 需 K3 接线项 / 未决风险。

**落盘约定**：移植批写 `porting/staging/<批次>/`，包名即为最终包名（合并=拷贝）；FIX 批直接改主树。

## 5. 权限边界

- flash 禁止：改需求、改注册名、改 `porting/*.md` 文档、git 提交、运行 gradlew（除 FIX 批被明确授权 compileJava）、触碰简报范围外文件。
- flash 必须：保留既有 TODO 标记、保留日文注释原文、遵守 `porting/MIGRATION_RULES.md`。

## 6. 超时与失败重试

- 超时（2h）→ 盘点已产出文件 → resume 续跑（附进度指令）；
- 429/520 → 退避 60-90s → resume；
- 同一批连续 2 次异常失败 → K3 人工接管该批或拆小重派；
- 所有故障/恢复记入 `porting/integration-notes.md` 事故台账。

## 7. 结果回传与汇总

- 完成通知到达 → K3 读报告 → 对照台账核对 P 项 → 合并 → `smoke_test.sh` 双模式回归 → 台账更新（批次状态板 + 回归闸门记录）→ git 提交。
- 台账是跨上下文唯一事实源：每轮合并前必读。
